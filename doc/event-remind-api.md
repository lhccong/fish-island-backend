# 通知未读数和全量操作

所有接口沿用现有 Sa-Token 登录认证及 `/api/event_remind` 前缀，接收者从当前会话取得，不允许客户端指定账号。前端与后端需一起部署，不需要数据库结构变更。

| 方法与路径 | 请求 | 成功响应 data | 范围 |
| --- | --- | --- | --- |
| GET `/my/unread/count` | 无 | 未读总数（Long，现有 JSON 配置序列化为数字字符串） | 本人的全部 state=0 通知，不受分页影响 |
| POST `/batch/read` | `{"ids":["通知ID"]}` | true | 仅指定 ID 中属于本人的通知，空 ID 列表报参数错误 |
| POST `/batch/set/read` | 无或原兼容请求体 | true | 本人全部未读通知，保持旧接口忽略 IDs 的语义 |
| POST `/all/delete` | 无或 `{}` | true | 删除本人全部通知，包括未加载记录；无法恢复 |
| POST `/batch/delete` | `{"ids":["通知ID"]}` | true | 保持原协议，校验所选通知均属于本人 |

全量已读、指定已读与全量删除在目标已处理或为空时仍返回成功；数据库异常沿用全局异常响应。新到达且晚于操作 SQL 的通知保留，由后续计数和列表请求反映。测试：`EventRemindActionsTest` 覆盖接收者条件、全量/指定范围及空集幂等。
